# XLeRobot v1.3.0 測試版｜部署說明

## 改版內容
- 依 2026/10/12 會議，更新總覽、討論重點、困難與展出、教授問答；舊內容以可收合區塊保留。
- 移除「方向清單」導覽按鈕，原始內容與程式仍保留作為歷史資料。
- 新增「採購清單」：新增／編輯／狀態／金額統計／CSV 匯出／圖片上傳與放大。一般組員可新增編輯，只有管理員可刪除。
- 新增 Email 通知管理介面：管理員勾選通知事件、開關及即時／10 分鐘彙整。
- 原有任務、成果附件、硬體、供電、歸還守則、安裝包與技術來源維持。

## 正式上線前（重要）
1. **先備份 Railway Volume `/data/data.db` 及必要附件**。此版在既有 SQLite 新增 `purchases`、`purchase_images`、`notify_queue`，不清除既有資料。
2. **不要直接覆蓋正式站測試**：先使用獨立 Railway Service 與獨立 Volume/SQLite。若要測試 Bucket 圖片上傳，也應使用獨立測試 Bucket 或測試路徑與資料。
3. 本版沿用 `server.py` 啟動：`python server.py`。健康檢查 `/api/health`。
4. 既有 `TASK_DB`、`ADMIN_KEY_HASH`、`AWS_ENDPOINT_URL`、`AWS_S3_BUCKET_NAME`、`AWS_DEFAULT_REGION`、`AWS_ACCESS_KEY_ID`、`AWS_SECRET_ACCESS_KEY` 沿用原本 Railway 設定。
5. Email 功能需要 Railway Variables：`SMTP_USER`（寄件 Gmail）、`SMTP_APP_PASSWORD`（Google 應用程式密碼）、`NOTIFY_EMAIL`（收件者）；可選 `SMTP_HOST`（預設 smtp.gmail.com）、`SMTP_PORT`（預設 465）。**不要提交密碼到 GitHub**。若 Gmail 帳號不支援應用程式密碼，需改用其他 SMTP 服務。
6. **Email 預設關閉**。設定好變數並測試後，由管理員在「採購清單 → Email 通知設定」開啟。寄信失敗不會阻止任務或採購資料儲存；未寄出的通知保留在 `notify_queue`，伺服器會重試。
7. 管理員驗證沿用原本「分工 & 時程」登入；登入後採購清單會在下一次權限檢查時顯示刪除及通知設定。

## 已執行的本機測試
- Python 編譯與 Node.js JavaScript 語法檢查。
- 以臨時 SQLite 啟動服務，測試健康檢查、採購新增、編輯、讀取、未登入禁止刪除、未登入禁止通知設定。

## 尚須在 Railway 測試
- 真實 Bucket 圖片上傳、檢視、刪除及 redeploy 後存取。
- Gmail SMTP 寄送與即時／10 分鐘摘要；目前沒有你的憑證，因此無法實測。
- 管理員登入後的權限與手機排版。

## 注意
- 10/12 會議未指定採購負責人與期限，網站未替組員預先填入。
- 目前展示流程為規劃，不代表整合功能已實作完成。

## 2026/10/12 最終需求增補（已納入此 ZIP）
- 採購項目增加「庫存確認：尚未確認／有／沒有」、「實際金額」、「報銷狀態：未開始／待送件／審核中／已完成／不需報銷」。採購狀態改為「待確認／待採購／已購買／已到貨／不需採購」。
- 負責人保留為選填欄位：僅管理員可指派、取消或變更；沒有指派時，公開卡片不顯示負責人欄位。
- 管理員可獨立控制組員是否「查看報銷狀態」及「修改報銷狀態」。兩者預設關閉；必須先允許查看才能允許修改。後端對 GET、PATCH 同步檢查權限。
- 報銷憑證可上傳多張 JPG/PNG/WebP 或多份 PDF，單檔上限 20 MB。管理員專用：列表、檢視、上傳、刪除均須通過後端驗證；商品圖片仍供組員查看。
- 報銷憑證存於既有 Bucket 的 `receipts/` 分類（無 Bucket 時使用本機 `UPLOAD_DIR`）；商品圖片使用 `purchases/`。採購項目刪除時一併刪除其圖片及報銷附件。
- Email 通知事件增加庫存確認、負責人指派、報銷狀態變更。預設六項重要通知事件不變，Email 總開關仍預設關閉，避免未配置憑證時誤以為已寄信。
- 新增資料庫結構：既有 `purchases` 表補上 `stock`、`actual_price`、`refund` 欄位；新增 `purchase_receipts` 表與 `purchase_permissions` 設定。採用 `ALTER TABLE` 補欄位，不刪除舊紀錄。
- **安全提醒**：管理員登入憑證仍沿用現有網站機制。由於一般採購編輯權限是共用開放模式，請避免在商品備註或商品圖片上傳個資、付款資訊；敏感單據僅上傳至「報銷附件」。

## 最終版測試補充
- 已使用隔離的臨時 SQLite、本機 HTTP 服務測試：新增採購、編輯、負責人指派、庫存與報銷權限切換、未授權拒絕修改、未授權拒絕下載報銷附件、管理員上傳／讀取／刪除 PDF、採購項目刪除，均通過。
- **尚未實測**：Railway Bucket 實際讀寫、Gmail SMTP 送信、實際瀏覽器手機版、完整正式資料庫遷移。請勿跳過測試環境驗證。
